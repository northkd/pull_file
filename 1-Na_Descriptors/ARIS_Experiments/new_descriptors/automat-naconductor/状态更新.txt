# Na 离子导体描述符搜索 — 会话交接（2026-08-13）

## 一、项目与真正的工作目标

**项目**：`automat-naconductor`（由 AUTOMAT 改造），从 CIF 晶体结构导出局域结构描述符，寻找与 log₁₀(室温离子电导率) 强相关、且经得起体系混杂控制的量。

**当前阶段的实际目标不是"找到好描述符"，而是确认这些算法在数学上估计的到底是什么量。** 问题分三类：

- **Bug**：代码没实现作者意图。占比很小。
- **合理性**：设计选择是否恰当。正反都能讲。
- **估计量身份**：代码正确执行了它写的东西，作者以为在算 A，数学上算的是 B。**占多数。** 例：`covalency_index` 忠实计算 `1−exp(−Δχ²/4)`，一个 bug 都没有，但它算的是离子性；`network_dimension` 忠实计算最大连通分量占比，它不是维度且永不返回 3；`max_bond_length` 被代码声明为 `a2_max_dist` 的别名，但两者是**两个独立函数**，该断言从未验证。

这类东西修不掉（没有东西坏了），只能重新命名或重新定义，**而这个选择必须显式做、且必须在见到数据之前做完**。

## 十一、协作方式（请沿用）

- **评审输出用「亮点 / 弊端」结构**，弊端走**拒稿视角**，不写鼓励性框架；结论用表格给判定（PASS / PARTIAL / FAIL / BLOCKER）
- **审计/评审报告直接作为回复正文输出，不生成文件**
- **给执行器的 prompt 一次排多项**，尤其把 git 记录/清账类杂项一次排完
- **每当回复里给出「下一步该做什么」，同一条回复里直接附上可粘给执行器的完整 prompt**
- 用户会粘执行器的**完整回复原文**（过长时会先问需要哪几段）
- 期刊/论文评价用**中科院分区**（大类分区 + Top）而非 JCR/IF；分区层级与实质判断分开陈述

**两条要提醒新会话的**：

1. **验收会自我延续。** 每一次不完美的交付都天然生成下一轮任务，而验收成本能无限自我增长。本对话中一度连续三轮在修"执行器报告的可信度"而非研究本身。判断标准：若剩下的问题都是文档级、不改变行为，就该封版，把它们随下一轮顺手带走。
2. **等待期填充。** 主线阻塞（等用户材料）时，容易用可做的事把轮次填满，于是阻塞看起来没那么显眼。287 这个数字曾三轮没动过，期间每轮都有真发现，但每一轮都不是主线。**排下一步时先问：这件事让 287 减少了吗？**
