# 2026-08-03 修复记录：结构描述符、评估管线与双轨 Agent

## 范围与结论

本次修复的目标是把 `automat-naconductor` 从“可能静默产生全缺失或
伪科学结果”的原型，收紧为一个可审计的结构描述符研究框架：CIF/特征不可用时
必须在写结果前失败；可用时，所有筛选、组合与验证都保留输入、公式、控制变量和
不可用策略的证据链。

本次**没有修改、删除或重新生成**以下内容：

- `data/naconductor_raw.csv`；
- 任一 CIF；
- `data/naconductor_featurized.csv` / `.json`；
- 任何既有研究结果目录。

因此，本次提交的是代码、配置、测试和文档修复，不是新的材料学发现。当前 checkout
所引用的 84 个 CIF 均不可用，真实 Pipeline/Agent 已被设计为明确失败，不能据此
输出任何“最佳描述符”或机制结论。

## 先澄清：NASICON=oxide、sulfide=sulfide 为什么在此数据中冗余

这里不是在说“NASICON 在物理上等于 oxide”，更不是说“sulfide 是恒等于硫化物”的
普适材料学定律。这里的“冗余”是指**当前 84 行数据的分类设计矩阵共线**：

| system | chloride | iodide | oxide | sulfide |
| --- | ---: | ---: | ---: | ---: |
| NASICON | 0 | 0 | 30 | 0 |
| sulfide | 0 | 0 | 0 | 41 |
| halide | 12 | 1 | 0 | 0 |

若已放入 system 的参考编码虚拟变量，再放入 oxide/sulfide 虚拟变量不会增加矩阵秩：
它们可由 system 完全表示。唯一可增加独立信息的是 halide 内的 iodide-vs-chloride
对比；但 iodide 只有一例，不能支持阴离子分层 CV。代码因此把 system 作为主控制，
只把**实际增加秩**的 anion contrast 用于残差化，并把其余列报告为冗余。这是对当前
抽样设计的统计事实，不是对材料体系的本体断言。

## 逐项修复记录

### 1. 带电 Species 下 Na/阴离子与占位识别错误

- 原始问题：Pymatgen 位点可能是 `Na+`、`O2-` 等带电 `Species`；原实现用字符串或
  未归一化对象与 `"Na"`/元素符号比较，导致 Na 位点、阴离子位点和部分 framework
  位点被漏掉。部分占位也没有在同一逻辑中累计。
- 根因：将化学元素身份和 Pymatgen 的带电物种显示表示混为一谈。
- 修改文件：`descriptors/_base.py`、`family_a_polyhedron.py`、
  `family_c_concentration.py`、`family_e_framework.py`、
  `family_g_electronic.py`、`family_h_symmetry.py`。
- 新行为：新增统一的元素符号与按元素的占位归一化辅助函数；Na、阴离子、主骨架元素和
  Na 总占位均按元素身份识别。G 族电荷偏离使用实际氧化态时的
  `abs(net_charge) / total_absolute_charge`，只有缺少氧化态时才使用明确标注的回退估计。
- 回归：`tests/test_descriptor_basics.py` 覆盖 charged Na/O、混合占位和有限的 A/C/E/G/H
  结果。

### 2. Wyckoff diversity 恒为 NaN

- 原始问题：`compute_wyckoff_diversity()` 调用了当前 Pymatgen 对象上不存在/不匹配的
  API，异常被宽泛吞掉，结果退化为 NaN。
- 根因：使用了不稳定的对象属性而没有验证 API 契约。
- 修改文件：`descriptors/family_h_symmetry.py`。
- 新行为：基于 `SpacegroupAnalyzer.get_symmetrized_structure()` 的
  `equivalent_indices` 计算等价 Wyckoff 位点组数；仅局部屏蔽已知的上游 deprecation
  warning，不再把计算错误伪装为正常 NaN。
- 回归：`test_descriptor_basics.py` 的 Wyckoff 多样性用例在有对称性结构上要求有限值。

### 3. CIF 路径、预检与全缺失特征的静默成功

- 原始问题：相对 CIF 路径会受进程工作目录影响；缺 CIF 后可能先创建输出，已有的
  全 NaN 特征化文件也可能继续生成“空研究报告”。
- 根因：缺少 CSV 相对路径规范、输入完整性闸门和输出延迟创建。
- 修改文件：`descriptors/featurizer.py`、`run_pipeline.py`、`automat_utils.py`、
  `train.py`。
- 新行为：
  - Pipeline 特征化以 raw CSV 父目录解析相对 CIF，严格预检全部路径后才初始化描述符
    列或写 CSV/JSON；绝不回退到当前工作目录。
  - Agent 除路径存在外还对全部 CIF 做可解析性预检，且在任何 `results/agent` 工件前完成。
  - Stage 0 若没有足够有效的真实结构描述符，抛出明确的 regeneration 诊断；
    `results/pipeline` 在 Stage 0 成功前不会创建。
  - Pipeline 顶层把 `FileNotFoundError` 和全缺失特征作为受控的 `ERROR`/exit 2，而不是
    输出 Python traceback。
- 回归：`tests/test_featurizer_preflight.py`、
  `tests/test_evaluation_core.py::test_cli_fails_closed_when_featurized_artifact_has_no_valid_descriptors`、
  `tests/test_pipeline_integration.py::test_cli_missing_cif_fails_closed_with_a_clean_diagnostic`，
  以及 Agent 缺 CIF 回归。

### 4. 间隙位点几何不是周期性 Voronoi 顶点

- 原始问题：D 族以 Voronoi ridge 的中心/不正确候选代替真实空隙顶点，并用原胞欧氏距离，
  跨边界时可得到错误的大距离。
- 根因：Voronoi 数据结构含义与周期性边界条件没有一致处理。
- 修改文件：`descriptors/_base.py`、`family_d_vacancy_topo.py`。
- 新行为：从实际 Voronoi vertices 构造候选；使用周期性原子影像和 lattice minimum-image
  距离，并按周期最小像去重。D 族的间隙—Na 距离不会把跨边界的约 0.2 Å 误记为约 9.8 Å。
- 回归：`test_descriptor_basics.py` 覆盖真实 vertex 和最小像距离。

### 5. 描述符注册表、兼容 alias 与占位 NaN 描述符

- 原始问题：`max_bond_length` 是 `a2_max_dist` 的重复 alias，旧特征文件仍可能绕过默认
  过滤；`bottleneck_anisotropy`/`bvse_barrier_estimate` 在当前实现中没有可用计算结果，
  却可能参与自动搜索。
- 根因：注册表没有显式表示单位、维度、别名和“可自动搜索”状态。
- 修改文件：`descriptors/__init__.py`、`descriptors/featurizer.py`、
  `descriptors/deconfound.py`、`run_pipeline.py`。
- 新行为：保留所有公开 callable 以兼容旧代码，但元数据增加 `unit`、`dimension`、
  `active_for_search`/`searchable`、`alias_of`。alias 和两项永久不可用描述符均从自动
  特征矩阵、单描述符筛选、稳定性和组合搜索中排除；已有特征 CSV 也不能重新注入 alias。
- 回归：别名泄漏回归验证 canonical 列可用而 `max_bond_length` 不会进入 Stage 1/2。

### 6. 全局插补/标准化造成 CV 泄漏

- 原始问题：特征矩阵在分折前进行中位数插补和标准化；组合公式也可能在模型外被处理。
- 根因：把统计预处理误当成数据准备，而不是训练折内拟合步骤。
- 修改文件：`descriptors/featurizer.py`、`descriptors/cv_strategies.py`、
  `descriptors/stability.py`、`descriptors/combination.py`、`run_pipeline.py`。
- 新行为：原始描述符值和 NaN 原样保留；每个 Ridge/Lasso/CV 折新建
  `SimpleImputer -> StandardScaler -> model`。组合先在原始物理值上完成，再在每个训练折内
  处理整个完成公式；零分母和非有限分量保持 NaN，不使用 epsilon 或全局 z-score。
- 回归：CV、稳定性和组合的缺失值用例明确要求折内插补。

### 7. 重复子采样、少数类别和 LOSO 的错误/不透明行为

- 原始问题：重复子采样没有严格执行请求的次数、测试比例与种子；不可能的分层会把
  scikit-learn 异常暴露给用户。仅一个 iodide 时，anion CV 也可能被误解为可比较得分。
- 根因：没有把 CV 可行性视为显式结果状态。
- 修改文件：`descriptors/cv_strategies.py`、`descriptors/combination.py`、
  `run_pipeline.py`、`automat_utils.py`。
- 新行为：
  - `StratifiedShuffleSplit` 使用精确 `n_repeats`、`test_fraction`、`seed`；不可行时返回
    `skipped=True`、原因、空 folds 和 NaN 指标。
  - anion CV 对样本数不足类别明确 skip；可降折时报告 requested/effective folds 和
    `downshifted`。
  - 单体系 LOSO 在 Agent/组合验证中是明确 skip，不会杀死其它可用策略。
  - 综合分数只平均有限且未 skip 的策略，记录可用策略数和是否完整，避免把“缺策略”
    当成 0 分或成功证据。
- 回归：`tests/test_evaluation_core.py`、`tests/test_combinations.py`，以及本次端到端用例
  故意设置 1 个 iodide，断言 anion skip 而 LOSO/重复子采样仍执行。

### 8. system/anion 去混杂的秩与冗余没有审计

- 原始问题：system 与 anion 同时 one-hot 后被当作两个独立控制，掩盖当前数据中几乎完全
  的分类共线性。
- 根因：缺乏带截距、reference-coded 的设计矩阵秩审核。
- 修改文件：`descriptors/deconfound.py`、`descriptors/combination.py`、
  `run_info.yaml`。
- 新行为：`build_rank_aware_controls()` 先放 system，再逐列测试 anion contrast 是否增加
  秩；输出 system/combined rank、增量/冗余 anion 列、实际残差化列和
  `anion_is_independent_control=False`。组合 V2 复用同一构造，不能悄悄回退为“全部 dummy”。
  当前数据的审核结果是 system rank=3、combined rank=4、anion 增量 rank=1；oxide 和
  sulfide contrast 冗余，iodide contrast 是唯一增量。
- 回归：去混杂和 V2 因子跨越回归要求 system 主控制与冗余列可见。

### 9. Stability selection 实为 Ridge 系数启发式

- 原始问题：旧实现没有真正做子采样 Lasso，且可能被全局处理后的数值污染。
- 根因：方法名称和实际估计器不一致。
- 修改文件：`descriptors/stability.py`、`run_pipeline.py`、`run_info.yaml`。
- 新行为：每次无放回子采样都本地拟合 imputer/scaler/Lasso；只有非零 Lasso 系数才计为
  选中。输出方法、alpha、样本比例、次数、种子、噪声 95% 基线和空 schema。物理族排序按
  `abs(deconfounded_spearman)`，但保留相关方向。
- 回归：稳定性选择、空特征和物理族负相关代表用例。

### 10. Stage 1→2 合约和三元组合的真实可达性

- 原始问题：Stage 2 可重新把 Stage 1 拒绝的真实描述符纳入；更隐蔽的是，三元式规定为
  “同族两个 + 相邻族一个”，但每族只留一个代表时，在所有八族都有代表的数据中，Stage 3
  不可能生成任一三元式。旧的“缺族补额”还会使名义 `max_per_family=2` 扩张到 4，
  违反三元模式的有界搜索承诺。
- 根因：筛选池与组合语法的容量约束彼此矛盾，且物理族分组器把名义上限实现成了软上限。
- 修改文件：`run_pipeline.py`、`descriptors/stability.py`、
  `tests/test_pipeline_integration.py`。
- 新行为：Stage 2 只接受 Stage 1 预筛选的真实描述符和固定噪声；`max_descriptors=2`
  时每族保留一个稳定候选，`max_descriptors=3` 时每族最多两个。第二个名额是**仅为受限
  三元公式服务的候选池名额**，不是第二项独立发现。`main()` 把冻结配置的
  `args.max_descriptors` 同时传给 Stage 2 和 Stage 3。`PhysicalGrouper` 现在把该容量当作
  硬上限，缺失其它族也不会增加任何已存在族的名额。
- 回归：新的合成端到端测试覆盖所有八族、两个独立 A 族特征和 B 族特征，要求
  Stage 2→3 实际产生 `n_components=3`，而非仅在单元测试中手工伪造三元候选。
  另有直接分组器回归以四个 A 特征和缺失族为输入，要求三元模式下 A 至多保留两个。

### 11. 组合搜索存在重复、无物理方向的比例和全局数值变换

- 原始问题：`A+B`/`B+A` 等交换律重复被枚举；比例可任意反向；零分母加 epsilon；只支持
  成对公式，或不能证明三元公式沿合法邻接关系构造。
- 根因：公式搜索用隐式、顺序敏感的枚举而非显式物理规则表。
- 修改文件：`descriptors/combination.py`、`descriptors/__init__.py`、
  `run_info.yaml`。
- 新行为：
  - `itertools.combinations` 使加法和乘法仅有一个 canonical 无序对；
  - ratio 严格方向化，当前自动搜索只允许审查过的 A→C，且拒绝零/非有限分母；
  - 每个公式保留 components、families、operators、规则、原始值来源、缺失策略和
    “完成公式后才在模型内标准化”的 provenance；
  - 仅枚举 2 或 3 个描述符；三元式只能是同族两个加显式相邻族一个，并对加法做维度兼容
    检查；禁止 log/sqrt/power；
  - 组合读取 inactive alias/placeholder 时不会自动加入。
- 回归：`tests/test_combinations.py` 覆盖无交换律重复、无 epsilon、方向规则、维度检查、
  bounded triple 和空 schema。

### 12. 三元 CSV 往返、V1–V4 证据和报告 provenance

- 原始问题：CSV 会把 list/dict 扁平为不可验证字符串，Stage 4 可能把三元公式降级为 pair；
  组合验证也缺少计划要求的四种明确证据及不可用语义。
- 根因：结构化 provenance 没有序列化契约，验证只围绕单一 CV 分数。
- 修改文件：`descriptors/combination.py`、`run_pipeline.py`、
  `tests/test_combinations.py`、`tests/test_pipeline_integration.py`。
- 新行为：
  - Stage 3/4 CSV 对 formula 和 evidence container 使用严格 JSON；读取后要求
    `list[str]`、2/3 components、`n-1` operators、`d1/d2/operator/n_components` 和
    provenance 完全一致，不一致即报错，绝不静默降级；
  - V1 为体系内分量置换的 matched-formula 噪声基线；V2 为带 rank-aware 已知因素控制的
    折安全 OOF 目标残差预测（偏相关只作补充）；V3 为体系内 raw Spearman；V4 为体系分层
    bootstrap 区间；
  - 每个 block 都有 `available/reason/status=exploratory`，所有输出明确
    `causal_claim=false`，并记录没有 nested outer-group reselection 的不确定性；
  - Markdown/JSON 报告显示 components/operators、V1–V4、bootstrap CI、skip 和探索性
    解释边界。
- 回归：三元 Stage-3 CSV 重新读取后进入 Stage 4 的测试，以及本次端到端 Stage 3/4 JSON
  provenance 往返测试。

- 根因：运行配置不是单一可验证契约。
- 修改文件：`run_info.yaml`、`run_config.py`、`run_pipeline.py`、`README.md`、
  `program.md`、`.omo/plans/automat-reform-dual-track.md`、`pyproject.toml`。

  `results/pipeline/...` 输出，且输入路径相对所选 `--run-info` 解析。

### 14. Agent A 仍使用 Composition + RF + 预拆分旧栈

- 原始问题：`train.py`/`automat_utils.py` 仍以 composition 特征、随机森林、预拆分
  train/validation 文件和旧 logging 配置为中心，和结构描述符 Pipeline 不可比较。
- 根因：旧自动化 Agent 没有随研究问题从 composition 特征迁移到 CIF 结构描述符。
- 修改文件：`automat_utils.py`、`train.py`、`test_descriptors.py`、`run_status.py`、
  `plot_run_results.py`、`tests/test_agent_track.py`。
- 新行为：Agent 只接受显式的已注册结构描述符名；在全量冻结 raw CSV 上做 CIF 预检、
  单描述符计算、rank-aware 去混杂和共享的多策略折内 Ridge CV。旧 Composition/RF/
  train-val-test split 参数与语义移除；兼容文件名 `test_descriptors.py` 只作为结构审计入口。
  status/plot 只读取带完整身份列的 Agent TSV，停止策略只使用有限且已评估状态的
  deconfounded Spearman，不把 crash/skip 伪装成失败证据。

### 15. Agent 与 Pipeline 需要可并行但不能相互污染

- 原始问题：两条路径可隐式共享或覆盖结果，导致所谓独立验证事实上交叉读取/选择；输入
  批次和注册表版本也没有可核验身份。
- 根因：缺少冻结输入、输出根目录和 C9 边界的可执行约束。
- 修改文件：`automat_utils.py`、`train.py`、`run_pipeline.py`、`run_status.py`、
  `plot_run_results.py`、`run_info.yaml`、`README.md`、`program.md`、
  `.omo/plans/automat-reform-dual-track.md`。
- 新行为：两轨可以同时启动，但只共享 `shared_input` 中冻结的 raw CSV、活动描述符注册表
  路径和 revision；Agent 只能写 `results/agent/`，Pipeline 只能写 `results/pipeline/`。
  任何已有/新 Agent TSV 或审计 CSV 均须有单一且匹配的三项身份：
  `shared_raw_file`、`descriptor_registry`、`registry_revision`。C9 是用户授权后的只读
  跨轨审查点；在此之前双方不读取对方结果。
- 解释边界：两轨一致只能提高优先复核价值，属于独立三角验证线索；它不是因果证明。
- 回归：`tests/test_agent_track.py` 覆盖跨轨路径拒绝、未冻结/不匹配 raw、错误注册表、
  外来/混合批次结果拒绝、缺 CIF 写前失败和单体系 LOSO skip。
