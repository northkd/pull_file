## 1. AUTOMAT 是什么

AUTOMAT 是一个自动化材料发现框架，核心理念是：

1. **输入**：化学组成（如 Na₃Zr₂Si₂PO₁₂），不需要晶体结构
2. **描述符生成**：从组成自动计算 200+ 个化学特征（原子量、电负性、d电子数等）
3. **模型训练**：用随机森林 + 3 折交叉验证筛选特征
4. **循环迭代**：自动生成新组成、评估、保留最优

**核心代码入口**：
- `automat/automat/program.md`：框架契约定义
- `automat/automat/automat_utils.py`：`featurize_formula()` 仅接受 `Composition` 对象
- `automat/automat/descriptors/__init__.py`：`AVAILABLE_COMPOSITION_DESCRIPTORS: dict[str, Callable[[Composition], list[float]]]`
- `automat/automat/train.py`：3 折 CV + RandomForest

## 2. 核心约束：仅接受化学组成

AUTOMAT 的所有描述符函数签名统一为：

```python
Callable[[Composition], list[float]]
```

即：**输入是一个化学组成对象，输出是一组浮点数特征**。

这意味着 AUTOMAT 完全不使用、也不接受任何结构信息（CIF 文件、原子坐标、键长、键角等）。

### 与我们研究的关系

我们的研究需要从 CIF 晶体结构中提取局域结构描述符，如：
- Na-X 键长、Na 多面体畸变
- 通道几何、空位网络连通性
- 局域宽松因子（Na-X 最长键长 / 目标键长中心）

这些描述符的计算输入是**结构**，而非**组成**。同一组成可以有完全不同的结构（不同空间群、不同位点占据），从而产生截然不同的电导率。

**这就是不兼容的根源**：AUTOMAT 看不到结构，而我们最核心的信号在结构里。

## 3. 兼容性逐项评估（9 项）

| # | 评估维度 | 兼容性 | 说明 |
|---|---------|--------|------|
| 1 | 输入格式 | ❌ 不兼容 | AUTOMAT 接受 Composition；我们需要 Structure/CIF |
| 2 | 描述符生成 | ❌ 不兼容 | AUTOMAT 仅生成组成描述符；我们需要结构描述符 |
| 3 | 模型训练 | ✅ 兼容 | RF + CV 是通用方法，可直接复用 |
| 4 | 特征筛选 | ⚠️ 部分兼容 | AUTOMAT 用 RF importance；我们需 Stability Selection |
| 5 | 交叉验证策略 | ❌ 不兼容 | AUTOMAT 用随机 3 折；我们需要体系分层（LOSO/LLOSO） |
| 6 | 循环迭代 | ⚠️ 部分兼容 | keep/discard 循环思路可借鉴，但生成新"组成"→生成新"结构"需要完全不同的流程 |
| 7 | 输出格式 | ⚠️ 部分兼容 | AUTOMAT 输出 results.tsv 审计追踪可借鉴；但高维特征集 vs 标量描述符目标不同 |
| 8 | 实验记录 | ✅ 兼容 | idea.md 4 节格式（Hypothesis/Procedure/Results/Conclusion）可直接复用 |
| 9 | 小样本适配 | ❌ 不兼容 | AUTOMAT 为大数据集设计（1000+ 样本）；我们仅 80-90 个 |

### 关键不兼容项详解

#### 3.1 输入格式

```
AUTOMAT:  "Na3Zr2Si2PO12" → Composition → 261 个特征
我们需要: Na3Zr2Si2PO12.cif → Structure → 键长/畸变/连通性等标量
```

同一组成的 β-NASICON 和 α-NASICON 电导率可以差 2 个数量级，但 AUTOMAT 对它们生成完全相同的特征。

#### 3.2 交叉验证策略

AUTOMAT 默认随机 3 折 CV。但我们的数据有严重的**体系混杂**问题：

- 体系标签（NASICON/硫化物/卤化物）是最强预测因子
- 随机 3 折 MAE=1.34，而体系留一（LOSO）MAE=2.97
- 随机 CV 的好表现来自"偷看"同体系样本，而非学到物理规律

**正确策略**：体系分层交叉验证（LLOSO 或 nested LOSO），确保训练集和测试集没有同一体系的样本。

#### 3.3 小样本适配

AUTOMAT 用 RF + 261 维特征 → 103 个样本严重过拟合。

我们需要的方法栈：
- **特征数远小于样本数**：先物理筛选到 ~10 个候选描述符
- **Stability Selection**（替代简单 bootstrap ranking）：用 LASSO + 子采样 + 噪声基线
- **符号回归**：在筛选后的少量描述符上搜索最优公式

## 4. 总评与三条路径

### 总体匹配度：约 35%

| 路径 | 可行性 | 工作量 | 推荐度 |
|------|--------|--------|--------|
| **A. 直接使用** | ❌ 不可行（35%） | — | 不推荐 |
| **B. 改造 AUTOMAT** | ⚠️ 勉强（60% 改写） | 极大 | 不推荐 |
| **C. 借鉴范式，自建框架** | ✅ 可行（80% 工作流匹配） | 中等 | **推荐** |

### 路径 A：直接使用 — 不可行

核心矛盾无法解决：AUTOMAT 的整个管道围绕"组成→特征"设计，加入结构描述符需要重写输入层、特征层、验证层。

### 路径 B：改造 AUTOMAT — 等于重写

如果强行改造：
1. 重写 `featurize_formula()` → `featurize_structure()`（60% 代码量）
2. 重写交叉验证策略（从随机 k-fold 到体系分层）
3. 重写特征筛选（从 RF importance 到 Stability Selection）
4. 重写迭代循环（从生成新组成到生成新结构/描述符组合）

改造量 ≈ 60% 重写，且破坏 AUTOMAT 原有设计哲学，维护成本极高。

### 路径 C：借鉴范式，自建框架 — 推荐

**从 AUTOMAT 借鉴什么**：
1. `idea.md` 4 节格式（Hypothesis / Procedure / Results / Conclusion）
2. `results.tsv` 审计追踪（每次实验的参数和结果都留痕）
3. keep/discard 迭代循环的思路

**不借鉴什么**：
1. 组成描述符生成（换成结构描述符计算）
2. 随机 k-fold CV（换成体系分层 CV）
3. RF importance（换成 Stability Selection + 符号回归）

**自建框架的设计方向**：
- 骨架：autoresearch 风格（阶段式管道，每阶段产出完整研究记录）
- 输入签名：`Structure → float`（从 CIF 计算标量描述符）
- 验证：Spearman ρ + bootstrap 置信区间 + LOSO + Stability Selection
- 输出：可命名、可写公式、可物理解释的标量描述符

## 5. Q&A 关键追问与回答

### 5.1 AUTOMAT 输出的特征集合是什么？（Q 4.1.1）

AUTOMAT 输出的是一个**高维特征向量**（如 261 个特征），而非一个可物理解释的标量公式。

| | AUTOMAT 输出 | 我们的目标 |
|---|---|---|
| 形式 | 261 个特征名字 + 值 | 1 个可命名的公式 |
| 论文写法 | "我们用 261 个特征训练 RF" | "局域宽松因子 = Na-X最长键长/目标键长中心" |
| 物理含义 | 每个特征知道是什么，组合方式黑箱 | 公式完全透明，物理含义一句话说清 |
| 高通量筛选 | 算 261 个数→RF 预测 | 算 1 个数→与阈值比较 |

**结论**：AUTOMAT 的高维输出对我们的研究目标"不够好"——我们需要的是可命名、可写公式、可物理解释的标量描述符。

### 5.2 part1.py 中的空位处理方法（Q 5.1.1）

`part1.py` 中存在基于 occupancy 推断空位的代码（第 684-698 行）：

```python
# 从部分占位位点提取空位
partial_na = [(i, site, occ) for i, site, occ in na_sites if occ < 0.999]
# 空位总量 = (1 - occupancy) 之和
vacancy_amount = sum(1.0 - occ for _i, _site, _occ in partial_na)
# 对每个空位位点，找最近 Na，计算距离和连接数
for vi in vacancy_indices:
    per_na_distances = [(ni, float(structure.get_distance(vi, ni))) for ni in na_indices if ni != vi]
```

**这就是之前指出的"错误假设"**——它假设 CIF 中的 occupancy < 1 就是真实空位。

**问题**：72/103 个材料的所有 Na 位点 occupancy = 1，导致空位相关描述符 = 0，无区分力。

**但 Na-Na 网络分析是好的**：`build_na_network()` 函数（第 457-535 行）构建 Na-Na 连通图，计算连通分量数、最大连通分量占比、网络维度估计——不依赖 occupancy，只看 Na 位点的空间分布。

**改进方向**：
1. 删除 occupancy 推断空位的代码
2. 保留 Na-Na 网络分析
3. 新加 Voronoi 分解或 BVSE 找真实间隙位点

### 5.3 为什么不用 S(D)？（Q 7.1.1）

**S(D) = mean_e[ρ_e] / std_e[ρ_e]** 衡量描述符跨体系的稳定性。

但当前仅 3 个体系，3 个数据点算 std 极度不稳定：

| 体系数量 | S(D) 可靠性 |
|---|---|
| 3 个 | ❌ std 不稳定，S(D) 值跳来跳去 |
| 7 个 | ⚠️ 勉强可用 |
| 10+ | ✅ 推荐 |

**替代方案**：直接报告每个体系内的 Spearman，不做统计汇总：

```
局域宽松因子的体系内 Spearman：
- NASICON 内：0.xx
- 硫化物内：0.xx
- 卤化物内：0.xx
三个体系均保持正方向 → 跨体系稳定的证据
```

**如果以后数据增加到 10+ 体系**，S(D) 就变得有用。

### 5.4 噪声注入机制详解（Q 7.5.1）

**噪声描述符 = 用来建立"假发现基线"的参照物。**

#### 类比：考试作弊检测

往试卷里加 10 道完全无意义的题目，任何"答对"这些题的学生一定是蒙的。无意义题就是噪声——它们和"学生会不会"无关，答对纯属运气。

#### 具体做法

```python
# 真实描述符（有物理意义，从CIF计算）
"Na-X最长键长"       → [2.89, 2.52, 2.78, ...]
"Na多面体畸变均值"    → [0.05, 0.03, 0.08, ...]

# 噪声描述符（纯随机数，无物理意义）
"噪声_1"             → [0.37, -1.25, 0.82, ...]   # np.random.randn(103)
"噪声_2"             → [-0.11, 0.94, -0.56, ...]  # np.random.randn(103)
```

#### 用法：Stability Selection 基线

跑 Stability Selection 后，每个描述符（真的和假的）都有一个"被 LASSO 选中的频率"：

```
局域宽松因子：被选中 85%  →  远超噪声，真信号！
Na多面体畸变：被选中 70%  →  远超噪声，真信号！
某个弱描述符：被选中 18%  
噪声_7（最"幸运"的噪声）：被选中 15%  →  噪声基线
```

如果某个弱描述符的选择频率（18%）只比最幸运的噪声（15%）高一点，无法确定它是真信号还是碰巧。

**一句话总结**：噪声描述符就是 103 个随机数排成一列。它的作用是建立"纯运气能达到多高"的基线——真描述符必须显著超过这个基线，才能声称自己不是碰巧拟合的。

## 6. 最终建议

### 核心结论

**不使用 AUTOMAT，借鉴其范式自建框架。**

### 已确定的关键决策

| 决策项 | 结论 | 理由 |
|--------|------|------|
| 是否直接用 AUTOMAT | ❌ 否 | 组成→特征 管道无法容纳结构描述符 |
| 是否改造 AUTOMAT | ❌ 否 | 改造量≈60%重写，不如自建 |
| 描述符策略 | 两层：跨体系+体系内 | 主论文报告跨体系描述符，补充材料解释体系内 |
| 统计方法 | Stability Selection + 噪声基线 | 替代简单 bootstrap ranking，为论文提供严谨的假发现控制 |
| 体系去混杂 | 偏相关：从 logσ 中回归掉体系哑变量 | 区分"区分体系"和"体系内物理" |
| S(D) 跨体系稳定性 | 暂不使用（仅 3 体系） | 改为直接报告每个体系 Spearman |
| 空位处理 | 不用 occupancy 推断 | 改用 Voronoi/BVSE 或仅分析全占位材料 |
| 交叉验证 | 体系分层（LOSO/LLOSO） | 避免"偷看"同体系样本 |

### 从 AUTOMAT 可借鉴的要素

1. **idea.md 4 节格式**：Hypothesis / Procedure / Results / Conclusion
2. **results.tsv 审计追踪**：每次实验参数+结果留痕
3. **keep/discard 迭代循环**：逐步精炼描述符集合

### 下一步：制定组合描述符搜索的正式计划

当准备好进入实施阶段时，需要制定包含以下内容的详细计划：
- 代码文件结构
- 每步的输入/输出/验收标准
- 体系分层 CV 的具体实现
- Stability Selection 的参数设置
- 噪声注入的数量和评估方式
